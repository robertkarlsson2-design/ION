# Design System

> ION is a compiler — it has no UI of its own. This file documents the **CLI affordances + emitted-code style conventions** the Design advisor agent should check tickets against.

## Design principles

- **CLI output is the UX surface** — error messages, build progress, snapshot diffs. They are the product's face.
- **Emitted target code looks hand-authored** — no compiler watermarks, no banner comments, no `// generated by ION` headers. Drop the artefacts into a TypeScript project and they should be indistinguishable from human-written code.
- **Deterministic output ordering** — same source → same emitted lines in the same order. Tests rely on this; consumers rely on this.
- **Errors point at wire-format source lines** — every error message references the `.ion` file + line/column, never the emitted target.

## CLI conventions

- **Subcommand layout**: `ion <verb> [args]` — `build`, `check`, `fmt`. Verb-first; no global flags before the verb.
- **Exit codes**: 0 success, 1 build error, 2 invalid args. Stable across releases.
- **Progress output**: minimal by default; `--verbose` for per-file timing; `--debug` for compiler internals.
- **Error format**: `path/to/file.ion:line:col error[E####]: message` — matches the format VS Code's problem matcher expects.

## Emitter style conventions

### TypeScript emitter
- 2-space indent
- Single quotes for strings unless template literal needed
- Semicolons at statement end
- Arrow functions for top-level callables; `function` for class methods
- `const` over `let` over `var`
- No `any` in emitted code unless source explicitly opted in

### Python emitter
- 4-space indent (PEP-8)
- Snake case
- Type hints on every function signature
- No `from typing import *`

### React emitter
- TSX output
- Functional components only
- Hooks-based state
- Props typed via TypeScript interfaces

## Snapshot conventions

- Golden corpus under `tests/snapshots/`
- One subdirectory per language target
- Snapshot files are committed
- Updating a snapshot is its own PR, separate from the emitter logic change that caused the diff

## Patterns we deliberately avoid

- **Compiler watermarks in emitted code** — no `// generated` headers, no `/** @autogen */` JSDoc
- **Non-deterministic outputs** — no timestamps, no `Math.random` IDs, no Set iteration where order matters
- **Cute CLI flair** — no emoji in default output, no colour escape sequences when stdout isn't a TTY
- **Surface-syntax in committed `.ion` files of consumer repos** — surface is for humans-reading-docs only

## How the Design agent uses this file

For tickets that change emitter style or CLI UX:
- Does emitted code still look hand-authored?
- Are outputs deterministic?
- Do error messages reference `.ion` source lines, not emitted artefacts?
- Are snapshot updates in their own PR?

Advisory only — never blocks.
