# Maintenance Checklist

## What to check

### Codebase
- Tests: `npm test` (vitest) — flag any regression. **Emitter snapshot tests MUST stay green** unless a PR explicitly updates them.
- Lint: `npm run lint`
- Build: `npm run build` produces `dist/cli/ion.js`; running `node dist/cli/ion.js --help` exits 0
- Dependency audit: `npm audit --audit-level=high`
- CLI smoke: `node dist/cli/ion.js build tests/fixtures/hello.ion --target typescript --out /tmp/ion-smoke.ts` produces a file that passes `npx tsc --noEmit /tmp/ion-smoke.ts`

### Deployment
- ION is a CLI compiler — there's no deployment to probe. Skip the deployment section.
- Confirm `npm link` still installs the binary cleanly (try `which ion` after `npm link`)

## What's deliberately out of scope

- Consumer repos' health — ION just emits; downstream repos own their builds
- Hand-authored surface-syntax `.ion` files in consumer repos — that's a consumer's concern
- A hosted compiler service — not on the roadmap

- Document specific flakes here as they're identified

## Custom invariants

- **Deterministic output**: run the compiler twice on the same fixture; outputs must be byte-identical (`diff` should produce nothing)
- **No watermarks in emitted code**: `grep -rE '(generated by|@autogen|// ION)' tests/snapshots/` should return nothing
- **Snapshot corpus + emitter changes in separate PRs**: a PR that changes both emitter logic AND snapshots is suspicious — flag for human review
- **CLI exit codes stable**: smoke tests cover 0 / 1 / 2 paths

## How the maintenance agent uses this file

Each weekly run:
1. Reads this file.
2. Runs codebase audit (tests, lint, build, dep audit, recent commits).
3. Skips the deployment probes (compiler has no deployment).
4. Posts ONE `## Weekly Maintenance Audit — YYYY-MM-DD` comment.

Never modifies code or files separate tickets. Humans triage the summary.
